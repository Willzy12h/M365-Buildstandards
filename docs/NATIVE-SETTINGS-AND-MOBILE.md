## Outlook mobile account setup by hand

Before: verify approved pilot identities, Exchange Online mailbox entitlement, Intune entitlement, supported Outlook and enrolled devices. Android requires Android Enterprise and Outlook from Managed Google Play; verify ENR-006. iOS/iPadOS uses enrolled managed-device app configuration; supervision/Apple Business Manager/VPP is not required by this procedure. Record existing app configurations, assignments and protection/Conditional Access dependencies. Do not treat tenant subscription counts as user entitlement.

1. Intune admin centre > Apps > App configuration policies > Add > Managed devices. Create separate iOS/iPadOS and Android Enterprise policies for the correct managed Outlook app. Keep assignments empty while reviewing the proposal.
2. Use the supported configuration designer's account setup controls and the Microsoft account-setup reference. The documented keys are `com.microsoft.outlook.EmailProfile.AccountType` = `ModernAuth`, `com.microsoft.outlook.EmailProfile.EmailAddress` = the user's primary SMTP address, and `com.microsoft.outlook.EmailProfile.EmailUPN` = the user's sign-in UPN. These can differ; inspect the directory attributes rather than deriving one from the other. Select supported Intune dynamic attributes in the designer instead of hard-coding an engineer's account.
3. Review the configuration and export before/desired settings. Do not enable organisation-only accounts mode or change general/data-protection settings under this recommendation; those require separate decisions.
4. Only after independent pilot approval, assign the reviewed policy to the exact pilot population. Record object IDs and effective assignments. Keep existing app protection and recovery paths intact.
5. Verify policy delivery status, then open Outlook on the enrolled pilot device. Expected result: the correct work account is offered, the user completes modern authentication, the intended mailbox works, and no unrelated account/profile changes occur. Inspect applicable protection/Conditional Access results separately. Test differing SMTP/UPN and an excluded user; record collection/configuration/functional results separately.

There is no executable Graph/PowerShell creation template for this action. The Microsoft resource models require different iOS/Android payloads and managed-app references; the current compiled write surface does not accept app-configuration creation. A future implementation needs its own reviewed transport guard, complete before/after capture, typed tenant approval, durable intent, single-attempt semantics and negative tests.
