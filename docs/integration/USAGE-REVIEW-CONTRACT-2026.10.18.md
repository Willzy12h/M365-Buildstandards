## Reuse and exact read surface

Reuse existing `Core.Reporting.GraphReportRegistry`, `Engine.Reports.GraphReportService`, `GraphClient.ForReports`, verified MSAL provider, report export/context admission, `LicenceInventoryService` and exact-ID mailbox-capacity evidence. New usage transport is deliberately separate because these APIs return a preauthenticated download redirect instead of the current paged JSON collection. Do not globally relax Graph redirect/route checks or introduce another cache/authentication flow.

Admit only public-cloud v1.0 GET of these fixed functions, with a typed period enum `D7|D30|D90|D180`, default D30:

- `/reports/getOffice365ActiveUserDetail(period='<period>')`
- `/reports/getEmailActivityUserDetail(period='<period>')`
- `/reports/getTeamsUserActivityUserDetail(period='<period>')`
- `/reports/getOneDriveActivityUserDetail(period='<period>')`

No date function, arbitrary query, report-settings read/write, directory export, application-only token or fallbacks. The four functions are independently selected with their own status/refresh time. Reuse approved `Reports.Read.All` only when actually returned by the verified connection; appropriate delegated reporting roles and workload licences can still refuse access. Never auto-grant access or recommend Global Administrator as a fallback. Navigation/selection makes no request; native action is experimental/default-off with explicit read acknowledgement and source/access preview.

## Download and admission boundary

Freeze exact endpoint/period, tenant/account, Graph audience, returned scope set and current presentation generation. Recheck context before acquisition/send and after each await. Retain only the existing one silent 401 renewal on Graph; no interactive retry. A changed identity/scope/context refuses admission. Token acquisition and all downloads share a five-minute request budget.

Handle the documented **302** explicitly with automatic redirects disabled. Accept only `https://reports.office.com/data/download/<opaque path>` on exact host and default443, no user-info, fragment, controls, IP literal or encoded path traversal/separator ambiguity. A URL comes only from the current authenticated response's Location header; a form, imported report or script cannot supply one. Reject an unrecognised download host rather than silently generalise the allowlist. A verified Microsoft endpoint change needs a contract amendment.

Use a separate no-cookie/no-default-credentials client with **no Graph Authorization header**, even on the first download; reject further redirects. Keep the complete preauthenticated URL solely in request memory and redact it from exception text, logs, evidence, filenames and support bundles. Store only the registered source and download host, not its secret-bearing path/query. Bound streaming content before allocation to 10 MiB per selected CSV, 20,000 rows and 256 columns; five-minute total; cancellation/context checks while streaming. A truncation or missing body is Partial/Failed, never empty success. No Range/resume/cache of bearer URLs. Admit the documented application/octet-stream download as well as text/csv, but validate the body as strict UTF-8 CSV (optional BOM) with quoting/header/row-width checks before projecting; a media type alone proves no CSV validity.

Use fixed per-report schema definitions from Microsoft's published CSV header examples. Preserve explicit extra future-column names in a bounded diagnostic, not arbitrary values. Missing required identity/time/value columns make that report unable to assess; duplicate headers, invalid encoding/quoting, malformed/coerced dates or numeric counts refuse admission. Zero is valid only from a returned valid zero. Blank activity date is “no date reported”, not zero activity, never proof an account is unused. A body with headers and no rows is successful empty only when it is otherwise valid and not cut off.

## Identity, privacy and safe suggestions

Microsoft conceals user IDs, UPNs and names by default. Do not infer privacy state from a GUID-looking ID, an email-looking value or a label. Preserve `Concealed`, `Identifiable` or `Unknown` provenance only when established by the report/source; otherwise use Unknown. No report-settings permission or privacy toggle is bundled. Human-declared provenance is labelled as such, never a verified tenant setting. None of these four published CSV schemas returns a privacy-setting flag. Therefore their initial automatic capture alone cannot establish Identifiable provenance or enable verified joined suggestions. Preserve useful separate usage views and show the specific missing provenance; do not mark the joined recommendation requirement complete. An independently admissible privacy source needs an explicit contract amendment and any new access approval before use. GET /admin/reportSettings is documented with ReportSettings.Read.All, which is not included in William's existing Reports.Read.All approval; this proposal neither requests nor silently adds it.

The active/email/OneDrive examples provide UPNs but no object IDs. Preserve these as **report identity text** and show their usage rows separately; do not join them to licences/capacity by UPN, display name or product label. Teams documents `User Id` but concealment can also apply. Cross-evidence association requires an established non-concealed canonical Entra object ID, exact match to captured user/licence identity, same tenant and compatible capture period; otherwise the row stays unjoined, including plausible-looking or ambiguous values. No attempt to reverse privacy masking, resolve names or create fabricated GUIDs. Deleted users, deleted-date mismatch, duplicate identities, renamed/reused text and incompatible intervals stay explicit.

Reuse exact user/SKU/service-plan licence evidence and mailbox `ExternalDirectoryObjectId` only after that admission. Usage report “Assigned Products” text is not a licence entitlement source. A mailbox's configured quota or storage does not prove entitlement; Business Premium alone does not prove a 100 GB primary quota. Preserve current licence/capacity evaluator meanings.

Suggestions are conservative and reproducible from a fixed as-of clock: “review business need” for an identified account with an observed assigned service and complete compatible evidence reporting no activity within the chosen period; “unable to determine” for missing activity values, privacy, service failure, partial capture, stale/incompatible sources or unmatched identity. Blank dates alone never qualify. Cross-service missing evidence cannot become an all-services inactivity claim. Show each fact, capture/refresh time, requested/actual period, join source/digests and reason. Active-user CSV does not return Report Period: keep its requested period distinct from unavailable returned-period evidence. Last-activity dates may predate the selected period; compare those dates conservatively, never reject or recast a legitimately older last activity as zero. No automatic licence removal, purchase, entitlement change, savings estimate or guarantee that a selected licence is unnecessary. Business/retention/legal ownership and downstream dependencies still need review through existing lifecycle controls.
