## Registered incident context

Add one fixed public-cloud delegated report over GET `/security/incidents`, using the existing verified Graph connection, bounded report transport, strict source/evidence dispatch and shared native/CLI/export infrastructure. Freeze a deliberate UTC createdDateTime interval, start inclusive/end exclusive, at most31days and never beyond the capture clock; freeze exact supported severity/status filters, if offered, before acknowledgement. URI-encode generated OData, do not accept arbitrary queries. The documented list API supports `$filter`, `$top`, `$skip`, `$count` and `$expand`; this reader uses only registered date/filter, bounded `$top` and admitted same-resource pagination. Do not assume `$select` or `$orderby` support. Do not expand alerts or fetch related entities, files or comments. Incident details are not a new remediation endpoint.

Retain only bounded observed incident ID, display name, created/update UTC timestamps, raw severity/status/classification/determination, nullable priorityScore, redirectIncidentId and incidentWebUrl text. Drop unrelated response content before evidence admission; no alert bodies, comments, descriptions, identities, attachments or tokens are retained by this adapter. Unknown/future enum values stay raw/unclassified; missing/null priority is Unknown, not0; status resolved is Microsoft's reported workflow state, not proof that the tenant is safe. Redirected incidents retain the stated target ID without following it or counting a merged incident as a new verified event. Duplicate/ambiguous IDs remain explicitly partial, not silently deduplicated.

Use the existing optional-access setup/connect pattern, default off, with exact returned SecurityIncident.Read.All and current verified tenant/operator/resource binding. Document Microsoft’s delegated roles: Security Reader, Global Reader, Security Operator or Security Administrator, or a suitable custom role. Scope consent alone does not establish RBAC or workload entitlement. Read failures/unsupported/licence-limited APIs remain Unable to check, not “no incidents”. No application-only fallback, SecurityIncident.ReadWrite.All or Directory.Read.All. Changing access/parameters invalidates reuse and acknowledgement; no sign-in on navigation or interactive retry during capture.

Business Premium/Entra P1 must not imply P2 Identity Protection access or complete Defender coverage. Actual incident availability depends on licensed/connected Defender workloads, assigned roles, retention and source coverage. Show these limits in original evidence, native view and every export. Risky-user/risky-sign-in APIs are not bundled into this report. A successful empty response means no incidents returned for that exact completed query, not no attacks, no risks or full tenant protection. Retention is reported as unavailable where the service does not return it; never invent a30/90day guarantee.

Apply shared16MiB/5000rows/100actualrequests/five-minute caps, source time/version, partial preservation, same-origin/resource/query pagination, single silent401 renewal, no retry after malformed/failed continuation and current-context admission. Cap/failed/cancelled reads retain earlier rows with a partial reason; they never become complete deployment before-evidence. Original bytes, pending-result recovery, immutable managed evidence, backup and historical/untrusted import reuse the existing contracts without expanding old-family meanings.

Native Reports offers explicit interval/access/coverage review, acknowledgement, Read/Stop, virtualised filters and HTML/CSV/Excel/original JSON. Offline CLI exports the same stored result; no live authentication. Treat incident URLs as untrusted text. A deliberate external-link action may allow only an exact returned HTTPS `security.microsoft.com` URL with the expected incident path/ID and matching source-tenant query; reject credentials, alternate ports, ambiguous/unknown query/path and script/file/custom schemes. Unsupported links stay copyable text with manual portal guidance. No automatic opening, embedded authenticated portal or native/browser command bridge.

## Strict external-results import

Add a separate `external-check-results` schemaVersion1 envelope, not a native assessment or snapshot schema. Required: tool name and explicit version, source run identifier, claimed tenant GUID, UTC performed-at timestamp, declared source read/completeness state, original result rows and canonical digest. Each bounded row has a unique source test ID, source-declared outcome, short plain-text title and optional plain-text reason/reference. Known source outcomes remain `Passed`, `Failed`, `Skipped`, `Error`, `Unknown`; future/raw values are `Unclassified`, never native compliant or pass. Failed/partial source execution cannot be labelled a successful complete benchmark merely because remaining rows passed.

Maximum8MiB, JSON depth16,5000rows,200characters per ID/version and4096characters per explanatory text; reject duplicate JSON keys case-insensitively, duplicate test IDs, unknown structural fields, null required values, invalid timestamps/tenant IDs/digests and unsupported versions. No ZIP extraction, executable expressions, embedded HTML, script execution, arbitrary object graphs, file references or remote fetch. Render text with existing HTML/CSV injection protection. Preserve exact original bytes and source digest; validation proves shape/integrity, never source authenticity or that tests actually ran. Imported source tenant must match the deliberately selected client, while the UI continues to label that tenant identity as a source claim.

The first supported interchange is this explicit neutral envelope, with a synthetic example/template and field instructions. It can carry manually prepared Maester-style results but is **not** a direct importer for arbitrary Maester/Pester/vendor JSON and must not be labelled as one. Unknown vendor schemas are refused with a conversion-format explanation, not guessed or loosely searched for a “Passed” property. Automatic vendor adapters would require a pinned documented source format and tested mapping through the same admission boundary; no such adapter is claimed in this decision.

Native import is a deliberate local file choice with source/tool/version/time/tenant/provenance preview, unknown/partial/error counts, searchable rows and complete exports. No source execution or managed insertion before validation. Preserve pending original recovery and context invalidation; a late import cannot appear under a newly selected client. Historical imported claims cannot satisfy assessment coverage, deploy before-evidence, jobs/completion, exact approval or recovery verification. No automatic remediation suggestions or scripts are generated from imported text.

## Reference mappings, not substituted compliance

Allow explicit reference links from a source test/incident to an existing control only against an exact loaded standard release and verified digest. Store the link as an engineer-entered reference with source ID/digest and target control ID, not a verdict translation, lineage mapping or toolkit ownership. Missing/renamed controls or unavailable historical standards remain unresolved; never rebind to the current release by name. Show configuration assessment, incident context and external claimed outcomes separately. No imported pass contributes to native compliance counts or closes a remediation/job. Provide existing first-party documentation/portal references without new permissions; do not replace the endpoint-security standard with vendor defaults.
