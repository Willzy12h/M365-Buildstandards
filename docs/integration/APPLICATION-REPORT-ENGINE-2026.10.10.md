# Application metadata report engine — PR #87

INT-094 is merged. This source slice implements application-expiry and application-consent engines, strict report schema 2, immutable persistence and full exports. It does not yet wire desktop/CLI report selection or the saved-evidence browser. Existing five schema-1 reports retain their exact registrations and strict entry points. New schema-2 data must use ReportEnvelopeDispatcher; it is never converted or resealed as configuration/deployment evidence.

Expiry records applications and service principals separately, with metadata-only password/key entries and independently bounded owners. A fixed collection end and explicit horizonDays integer (1–365, default 30) classify valid intervals; missing, malformed, zero or duplicate keys/dates remain Unknown/Partial. Secret values, hints, passwords, certificate/key bytes and raw response nodes never reach evidence or exports. Consent separates principal metadata, observed delegated grants and observed application-role assignments. Exact unique object/resource/role IDs drive joins; opaque assignment IDs are preserved. Requested permissions, effective use and replication are separate limitations.

Source statuses and intervals are explicit. Defaults preserve 5,000 rows/section, 32 MiB evidence/file and a maximum five-minute read budget, plus 256 credentials/object, 100 owners/object, 256 role definitions/principal, 256 assignments/principal and 256 child objects/report. Every omitted/failed/cancelled read remains explicit; combined limits retain their reasons. Existing HTTP page buffering is unchanged and is not described as a new transport-body limit.

The engine reuses GraphClient.ForApplicationReports(2, reportId), the current provider/transport and a separate read-only route allow-list. It neither authenticates nor requests consent. Identity/operator/client/account/mode/scopes and original connection timestamp are pinned through final acceptance, including empty final responses. Natural elapsed original token time permits existing silent renewal; timestamp/authority mutation refuses. Existing write/setup opt-in expiry and all deployment safeguards are unchanged. APPLICATION-SETUP records existing access and missing Directory.Read.All semantics.

EvidenceStore.SaveApplicationReport/LoadApplicationReport uses the existing immutable writer/path through a partial class. Strict readers reject duplicate/unknown fields, numeric-string parameters, schema/ID mismatches, tampering, unsafe file links, tenant mismatch and over-bound content. JSON/HTML/CSV/Excel exports preserve original sections, nested child rows, source intervals/read states, fixed end/horizon and supplied-file provenance. Filters must remain presentation-only when wired.

Isolated strict Linux selection: 131 cases passed (71 new and 60 existing Graph/report/export/scale/route regressions), zero failures/skips. Strict Windows-targeted App compilation passed with zero warnings/errors; this is compilation, not native execution. Removing unknown-field refusal produces three expected failures with nine controls; removing final context admission produces two expected failures with four controls. Fixed source was restored. Product-checkout validation, exact-source Windows CI and Claude review are required before merge. Live Microsoft and human gates remain blank.
