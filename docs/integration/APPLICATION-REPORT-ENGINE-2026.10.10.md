# Application metadata report engine — PR #87

INT-094 is merged. This source slice implements application-expiry and application-consent engines, strict report schema 2, immutable persistence and full exports. It does not yet wire desktop/CLI report selection or the saved-evidence browser. Existing five schema-1 reports retain their exact registrations and strict entry points. New schema-2 data must use ReportEnvelopeDispatcher; it is never converted or resealed as configuration/deployment evidence.

Expiry records applications and service principals separately, with metadata-only password/key entries and independently bounded owners. A fixed collection end and explicit horizonDays integer (1–365, default 30) classify valid intervals; missing, malformed, zero or duplicate keys/dates remain Unknown/Partial. Consent separates principal metadata, observed delegated grants and observed application-role assignments. Exact unique object/resource/role IDs drive joins; opaque assignment IDs are preserved. Requested permissions, effective use and replication are separate limitations.

Identity/operator/client/account/mode/scopes and original connection timestamp are pinned through final acceptance, including empty final responses. APPLICATION-SETUP records existing access and missing Directory.Read.All semantics.

EvidenceStore.SaveApplicationReport/LoadApplicationReport uses the existing immutable writer/path through a partial class. Strict readers reject duplicate/unknown fields, numeric-string parameters, schema/ID mismatches, tampering, unsafe file links, tenant mismatch and over-bound content. JSON/HTML/CSV/Excel exports preserve original sections, nested child rows, source intervals/read states, fixed end/horizon and supplied-file provenance.
