## Purpose and existing boundaries

Reuse `Core.Reporting.ExchangeReportRegistry`, `Engine.Reports.ExchangeReportEvidenceSchema`, `Engine.Evidence.ExchangeReportEvidenceStore`, the pinned private `Use-BditRead` wrapper, `App.Services.ReadOnlyRunWorkflow`, current typed forms, original-output recovery and HTML/CSV/JSON/Excel writers. This is not a general script runner or another authentication implementation.

No Exchange mutation, arbitrary command/URL/parameter, module installation, runtime fallback, execution-policy change, Graph-token transfer or service permission is authorised. Runtime support is the actual module's supported Windows PowerShell 5.1/PowerShell 7 combination; no promise that every installed version works.

## C1 — report/evidence identity extension

The current report reader assumes mailbox-GUID row identity; do not force edges, rules, logs or policies into that model. Retain outer `exchangeReportEvidence` schema1 and all existing report-schema1/adapter1 dispatch. The new fixed registrations use report schema2 and `registered-exchange-report/2`, with their own exact ordered sections/columns and typed rows. Registry definitions gain an explicit report-schema/adapter version; admission selects the exact registered pair, never guesses from columns or globally relaxes old GUID checks. New run IDs and tenant/account identity remain existing canonical GUIDs.

Each new row carries separate **source identity** and **local row key**. Source fields have declared namespaces and original values. The local key is a `sha256:` digest of a canonical typed tuple with explicit nulls; it is labelled a local observation key, never a Microsoft object ID, ownership claim or execution target. Per-section key derivation is fixed below. No random/fabricated GUID or name/UPN join. Raw principals may be unresolved; preserve that state rather than claiming the string establishes an Entra identity. Equal display names are not equal principals.

Reject duplicate local keys instead of silently dropping rows. If the source cannot distinguish otherwise identical entries, retain an explicit incomplete-source diagnostic and do not claim a complete ACL/inventory. Missing required source identity excludes that entry with a counted diagnostic, makes the section Partial, and does not turn an otherwise empty result into “none found”. Never fabricate an identity to retain a success claim. Returned empty lists, not returned lists, null values and failed reads remain distinct. Additional bounded diagnostics contain no credentials or message bodies.

For each target, record a typed read-state row even when it has zero returned entries. This distinguishes “queried successfully; no entries” from unqueried/failed/partial. Section completeness requires every selected target read to finish within limits. A successful empty child section cannot conceal a failed parent inventory.

Retain ExternalDirectoryObjectId and SMTP separately; neither replaces ExchangeGuid. Initial selection is 1–50 exact mailboxes, not an implicit estate-wide scan. Each manifest exposes only its listed typed parameters and numeric limits.

Permission and calendar reads preserve bounded raw strings and typed string lists, maximum 100 values per list and 4,096 characters per diagnostic, 1,024 per identity. Exact principal shape/property extraction must be pinned with synthetic module objects before its schema is implemented. Target-read keys use `(report ID, ExchangeGuid)` or `(report ID, group ExchangeGuid)`; folder-read keys add the returned folder identity; interval-read keys use `(report ID, exact UTC start, exact UTC end, frozen filter digest)`. If a module provides only a display label, store it as an unresolved raw label and do not infer SID/Entra object identity. No additional directory lookups/scopes are introduced to resolve it.

## C3 — trace intervals, completeness and limits

Microsoft documents the last 90 days, at most ten days per query and at most 5,000 rows per `Get-MessageTraceV2` call. Freeze a UTC clock and inclusive date selection, convert to explicit UTC interval boundaries, refuse future/reversed/out-of-retention dates and show the exact requested interval. If the final date is today, end at the frozen current instant and state that the current day is incomplete; do not query a future end-of-day or claim a full day. Use up to nine ten-day-or-shorter windows, including exact boundary de-duplication by the declared composite key (the sole duplicate-key exception: byte-equivalent rows from the overlapping boundary only). A duplicate with conflicting values is a diagnostic, not an arbitrary winner. Document boundary coverage rather than drop a day to avoid overlap.

Microsoft additionally requires MessageTraceId for messages sent to more than 1,000 recipients. Offer that exact GUID separately from the Internet MessageId. A general sender/recipient/MessageId query persists a high-recipient population limitation and stays Partial for exhaustive recipient coverage even when unsaturated or empty; it may report that its API reads completed, never that no other messages/recipients exist. The next step is a separately selected exact MessageTraceId query, not just narrower dates. An exact-trace query can establish only that trace's requested interval coverage when all other reads/limits succeed. Synthetic cases must cover both query kinds and distinguish the two IDs.

The initial adapter does not implement the command's subsequent-query cursor. Ask for at most the remaining global row budget per window. Reaching that limit means **Partial**, including exact-cap results where further absence cannot be proved; do not advance and claim that saturated window is complete. Preserve earlier rows and show a narrower-interval/filter next step. A later cursor implementation requires a bounded contract/test amendment, not silent pagination assumptions. The reference calls this subsequent querying rather than ordinary pagination. Respect documented throttling; nine serial requests do not imply guaranteed access or retention.

All other reports: at most 50 targets, 5,000 total output rows across sections, 100 values per permitted list, 100 source-read calls and 300 seconds of collection within the existing owned-runner overall limit. Where supported, request remaining cap plus one and mark excess as Partial; never use Unlimited. The current private gate materialises command results before row admission; it does **not** enforce a child-memory limit, and the 32 MiB file check occurs after execution. C-CONTRACT-001 therefore makes a bounded collection amendment a prerequisite for these new registrations: the engine-owned private gate must enumerate each result into an exact registered projection, count at most 5,001 raw rows and at most 32 MiB of projected values before accumulating an array, and stop/refuse overflow before the body receives it. Project only fixed approved fields with the field/list limits above, never serialise arbitrary raw module objects. Preserve before/after identity checks; mid-read identity failure discards rows instead of retaining them as ordinary partial output. The wrapper must likewise bound emitted body sections before final serialisation. Use server ResultSize only where documented, for example Get-EXOMailboxPermission. Neither Get-EXOMailboxFolderStatistics nor Get-EXOMailboxFolderPermission documents ResultSize; both require the new bounded gate path. An unbounded command must remain unavailable until this new gate path is implemented and tested. Module-internal allocation is not a hard memory guarantee: add an owned-process private-memory watchdog at 1 GiB, checked at the existing poll interval, with truthful resource-limit termination and unconfirmed-cleanup blocking; document its sampling/overshoot limitation. This monitor supplements, never substitutes for, bounded projection. No OS or process limit is claimed to exist already. No automatic retry of failed module reads; preserve earlier admitted rows and explicit failed target. Cancellation and unconfirmed process cleanup retain the existing block on replacement runs.

Stored evidence remains bounded by the current reader/runner limits (including 32 MiB reader ceiling); do not raise them to fit larger reports. A result that cannot be safely admitted or saved stays NOT SAVED/failed with its truthful recovery state. Do not treat a completed PowerShell process or produced CSV as proof all checks succeeded.

## C4 — runner, UI, storage and exports

Each new body declares only its reviewed commands through the existing fixed private read gate, validated AST, package hash and manifest. Runtime parameters are bound as values, never concatenated into commands/Invoke-Expression. No generic pipelines or method allowlist expansion without a specific demonstrated need and review. Before and after each read, retain the existing module-observed tenant/account check and exact requested mailbox/group binding. Wrong account/tenant must produce zero report reads. New native forms discover the separately pinned registrations through the existing Scripts and reports catalogue. Show target, resource, access/roles, interval, collection limits, included/omitted population and experimental/live-unverified status before explicit acknowledgement/Run. Navigation makes no read. Formula/HTML escaping covers hostile mailbox/principal/rule fields. Existing offline CLI import/export remains offline; Copy/Save of old items keeps its established behaviour. No collected report becomes deployment evidence, a licence entitlement assertion, automatic incident remediation or job-completion authority.

`APPLICATION-SETUP`/`EXCHANGE-PURVIEW` describe each added command and Exchange RBAC/module requirements. Existing manifest role labels are a starting reference, not verified least privilege or proof every field is available. Use Microsoft's current cmdlet/Exchange RBAC documentation, present unavailable commands as failed prerequisites and never suggest Global Administrator as a fallback. No new Graph scopes or live consent are included. Security-owner controls remain authoritative.

## INT-131 refinement — exact multi-section manifest descriptor (20 October2026)

Status: decision-only refinement for approved C; no runtime, access, source acceptance or live action. Canonical base0ddb6fe. ### Exact descriptor and unchanged envelopes

- Keep library manifest `schemaVersion:2`. Existing schema1 manual items and schema2/report1 items keep library `outputSchemaVersion:1`, their current non-empty `outputSchema.columns` and no `sections` property. Preserve body IDs/hashes/meaning; wrapper-pin updates follow ordinary package pinning.
- Only exact registered report2/adapter2 items use library `outputSchemaVersion:2`. Their `outputSchema.columns` is the required empty array; `outputSchema.sections` is required and contains the exact ordered registry list of `{id,columns}`. Each section lists its exact ordered registered row projection. At most8 sections/40 unique columns each; actual registry cardinality/IDs/order are authoritative. This describes fixed package content, never caller-selected fields or commands.
- Refuse missing/null/extra/reordered/duplicate sections, union columns, unknown columns/revisions and any report1/schema1 descriptor containing `sections` (including explicit null). Do not silently infer a version from field presence or fall back to flat columns. Older readers refuse the new description; no old bytes are rewritten.
- `execution.outputKind:scriptReadResult` and `execution.outputSchemaVersion:1` remain unchanged: these describe the existing child envelope, not the library output description. The child envelope stays schema1, repeats exact `reportSchemaVersion:2`, and must match the frozen registered sections/columns/parameters/run/actor/pins. Stored `exchangeReportEvidence` outer schema1/report schema2/adapter2 remains as INT-128. Report1 bindings retain their exact older pair.
- Derive the private run request from the registry after exact manifest validation; the body cannot add sections, fields or source commands. Report2 limits use the registered5,000-row bound, per-target/interval diagnostics,32MiB evidence ceiling and accepted bounded producer/watchdog. No generic script/Graph route or mutation is added.

### One authoritative local-key encoder

Report2 child rows must contain the registered `id` member with explicit null. After exact envelope, actor, source-identity, parameter and section admission, the parent engine computes each local observation key from the registered typed tuple using `ExchangeObservationKey`; it refuses a non-null child key. Strict stored/imported evidence still requires the exact recomputed non-null key. This is an explicit new-report2 normalisation boundary, not relaxation of report1 IDs or stored readers. Keep all raw source identity members and unknown states; invalid/missing tuple inputs are excluded only with the contract's counted partial diagnostic, never replaced with names or invented IDs. Neither a null child key nor the derived key supplies execution authority.

This avoids duplicating System.Text.Json escaping/canonical hashing in Windows PowerShell5.1 and PowerShell7. Test Unicode, quotes, backslashes, explicit nulls, list boundaries and case preservation through the same parent codec; refuse forged child IDs and mismatched stored keys. No PowerShell assembly loading, new method allowlist, arbitrary native callback or browser bridge is introduced. Record normalisation provenance in the registered adapter identity; do not present normalised evidence as unchanged raw child-envelope bytes.

The existing `atLeastOne` rule intentionally checks presence of optional text inputs and excludes booleans. Preserve it. Add `atLeastOneTrue` only for schema2/report2 `exo-mailbox-permissions`, naming exactly FullAccess, SendAs and SendOnBehalf in registry order. All are non-required booleans defaulting false; at least one must be true before run preparation/process creation/authentication. Refuse this rule in manual/report1/other registrations, duplicate/extra parameters and non-boolean fields. Use the same shared input validator for native review and engine requests; no expression interpreter, automatic checkbox selection or permissions change. Add this bounded `ScriptInputs` change to the files above and prove old rule behaviour unchanged.
