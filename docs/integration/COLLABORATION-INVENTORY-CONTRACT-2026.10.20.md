## Explicit blocked portions — do not evade them

- Full SharePoint site permission inventory uses GET `/sites/{siteId}/permissions`, whose current delegated table requires **Sites.FullControl.All**. That access is not approved. Keep this route unregistered/blocked with the reason and manual verification guidance; do not add FullControl, application-only access or a script/SharePoint REST workaround.
- Delegated GET `/users/{id}/drive` (and the signed-in `/me/drive`) can automatically provision a licensed user's OneDrive. This is a documented tenant-side effect even though the verb is GET. It is **blocked in read-only inventory**. Do not call it to discover missing drives, label a404 as unlicensed, or use scripts to evade this boundary. The first admitted drive list is existing selected-site libraries only; it is not a tenant-wide OneDrive owner inventory. A separately safe discovery source requires its own reviewed contract.
- Team/group direct owners or members are not SharePoint site owners, sharing-link grants, inherited/item permissions or effective access. Full OneDrive grants, content/item scanning, link inspection, external-sharing capability and inheritance evaluation remain explicitly unavailable/manual. No empty-success placeholders or green compliance badges stand in for them.

## Observation and evidence meaning

Report source identity stays the verified connection tenant/account/app, while resource ownership remains unknown unless actually established by returned fields. Search-visible/accessibility is never labelled tenant ownership or complete coverage. Freeze search scope, exact selected site/group IDs and section choices with acknowledgement. No lookups by display name/UPN or automatic joining of unrelated owner/member records. Metadata changes invalidate the exact selection before child collection; service rename alone never establishes a new identity.

Site rows retain original ID/name/display name, returned site-collection hostname and bounded webUrl text, created/modified times and their read states. Library rows retain exact parent-site/drive tuple, reported name/type and original owner user/group IDs/names where returned, never inferred membership. Source webUrl remains untrusted text, not a native command or automatically opened navigation. Team rows retain selected exact group ID and actually returned provisioning/type information. Direct group-owner rows retain original object ID and returned type; limited-information objects remain partial/unknown, not users guessed from names. Microsoft currently documents that v1.0 omits service-principal owners, and owner enumeration is unavailable for Exchange-created, distribution and synchronised groups. Persist these population limitations in original evidence, native presentation and every export. For an identified unsupported population, do not claim an owner check ran: show unable to check/manual; unknown group provenance cannot establish complete coverage. Even an otherwise successful returned owner list has the documented service-principal coverage limitation, and an empty list never proves no owners exist. Team conversation-member rows retain original member ID/type, parent Team ID, actual user/tenant IDs, display name and raw roles. Report owner/member/guest only when supported by actually returned roles; missing/null roles are Unknown. A different user tenant is an observed tenant difference, not an inferred guest role. Unknown future roles/subtypes remain unclassified. No email/contact-method value is required for these joins or role claims.

Every parent/child source has independent status/reason/count, and required missing identity/list shape is partial/failed. Returned empty arrays mean no rows returned by that successful source, never “no permissions” or “no guests exist”. Failed/denied/unsupported/cancelled reads retain earlier observations and later NotAttempted states. Never drop duplicate/ambiguous identities into a falsely clean deduplicated result; show explicit inability to establish unique source identity. Evidence retains source time/version/limitations and original service IDs; integrity is not source authenticity or effective-access proof. Imported evidence is historical and cannot become deployment before-evidence, approval or completion.

Extend INT-134's strict16MiB/5000total-row/100request/five-minute operational evidence bounds, managed immutable source-tenant storage and unchanged32MiB backup boundary. At most50combined selected sites/groups;100nested roles per member/owner diagnostic. Bound response streaming and search result pages. Reaching a limit is Partial/Failed with an explicit reason, not silent clipping. Original pending bytes survive current-context invalidation; normal close/replacement wait for Save/Export/confirmed Discard, with forced-termination limitations visible. No retries after malformed responses or unauthorised host/path changes. Existing read transport's single silent401 renewal remains; no write/consent capability.
