# Offline prerequisite diagnostics

The shared engine diagnostic checks an ordinary, trusted extracted portable folder. Run `bdit.cmd doctor [--root <folder>] [--format text|json]` from the portable folder (PowerShell: `.\bdit.cmd doctor`), or `dotnet BuildStandard.Cli.dll doctor` in a developer build. Text is the default. Doctor is routed before the general CLI option parser and exception handler; default-root resolution stays inside its own sanitisation boundary. Settings and diagnostics also provides the same local checks under Offline prerequisite checks. No repair, installation, sign-in or script execution is offered.

The doctor owns its `Console.CancelKeyPress` handler and cancellation source for one invocation. Ctrl+C requests cancellation between bounded checks/files and attempts owned-probe cleanup; it does not promise immediate interruption of an operating-system read. Completed findings are retained in a Cancelled result and remaining required checks stay Unknown. The handler detaches on success, refusal, cancellation and failure; a queued callback after disposal is inert and cannot suppress a later command's Ctrl+C. Setup, callback and cleanup errors use fixed safe stderr and exit 3. Results are staged until lifecycle cleanup succeeds, so a cleanup failure cannot publish a buffered Ready claim. Consume complete output together with its exit code; partial output from an unusable stream is not a valid result.

`Ready` means all required local checks completed and passed. It does not certify publisher identity, tenant readiness, consent, a write approval, script execution or live capability. A source checkout without published `VERSION.json` and `SHA256SUMS.txt` remains `NeedsAttention`. This self-contained Windows x64 package needs no installed .NET SDK. Missing optional PowerShell hosts, unknown module loading/application-control policy and untested tenant roles stay visible without failing a Graph-only package. Host observations use the same fixed Windows PowerShell 5.1/PowerShell 7 locations as the existing runner; hosts are neither opened for content nor executed, and their versions are not verified.

The existing two-space `SHA256SUMS.txt` inventory is checked without changing its format. Defaults bound it to 1 MiB and 10,000 entries, each hashed file to 256 MiB, aggregate hashing (including settings/catalogue digests) to 2 GiB, structured documents to 4 MiB and `VERSION.json` to 64 KiB. Additional package inspection stops at 20,000 entries or 16 nested directory levels. Relative names are at most 240 ASCII characters, with segments at most 128 characters. The service's `OfflineDiagnosticLimits` can be configured by its caller; the CLI offers no limit override. Exceeding a bound is `Unknown`, never a successful truncated check.

Inventory entries must use ordinary relative paths under the actual package areas (`app`, `standards`, `config`, `docs`, `licenses`) or the named portable root files. The immutable standards inventory includes `standards/lineage/manifest.json` and one-level `lineage-<safe-catalogue-name>.json` files; those bytes are hash-checked without rewriting historical data. A safe entry outside the supported inspection scope is reported separately from an unsafe path or link, and its contents are not read. Duplicate paths, case aliases, rooted/traversal/alternate-stream paths, reserved device names and links/reparse points are refused. UNC/device roots are refused before filesystem access. Root ancestors and component ancestors are checked before opening, and admission is checked again before reading. These managed checks are observations of a stable trusted folder; they are not an atomic defence against another process replacing filesystem objects concurrently. Do not run the diagnostic in an actively modified or adversary-controlled extraction. Unsigned adjacent hashes detect modifications only against that inventory; compare the ZIP with an independently trusted reference before use.

Engineer-editable `config/toolkit.settings.json` is validated with `ToolkitSettings.Validate`; a changed valid setting is distinct from an immutable binary/catalogue mismatch. The selected default catalogue uses the existing manifest algorithm/digests and `StandardsLoader.Parse` validation. Historical catalogue bytes remain unchanged. Additional entries are counted without reading their contents or printing their names. Profiles, tenant evidence, caches, tokens, credentials, secrets, existing logs, report contents and transfers are excluded from content inspection and recursive enumeration, even if listed by an inventory.

Writable checks exclusively open a uniquely named `.bdit-doctor-<id>.tmp` with `CreateNew` in each of `config`, `data`, `logs` and `reports`, write one byte and attempt deletion. A collision never becomes owned and is neither overwritten nor deleted. Only owned probes are cleaned up; no destination folder is created and no ACL/security setting is changed. For an absent destination, a temporary file under the existing root tests parent-create capability only, not the future folder's ACLs. Failed or unconfirmed cleanup is a required finding; a cancelled probe still attempts cleanup. An unexpected failure emits safe stderr and may require manual review of a leftover temporary diagnostic file.

JSON is a separate `kind: offlinePrerequisites`, `schemaVersion: 1` result. Text and JSON expose the same safe shared findings and next steps, without absolute roots, user/machine names, metadata `builtOn` values, settings values or raw operating-system exception text. The handler owns sanitisation, including failed output streams, before the general CLI catch can print an exception. Exit codes are 0 for required success, 1 for required Fail/Unknown (including admitted access failures), 2 for invocation/root refusal without a result, 3 for an unexpected sanitised failure, and 130 for cancellation with completed checks retained and remaining required checks Unknown. The existing unknown-command exit 64 is untouched.

Synthetic Linux tests exercise native symbolic links, bounded inventories, mutable settings, existing validators, private-error sanitisation, no private content reads, probe collisions/cleanup failures, cancellation and actual-handler/shared-result parity. Actual CLI subprocess tests verify early dispatch, strict options, safe explicit/default roots, output parity and file preservation. Deterministic console-event delivery tests cover cancellation forwarding, callback/disposal races, later-command behaviour and staged-output refusal on lifecycle errors; these are not native console acceptance. Windows tests use reparse attributes through the narrow fault seam instead of requiring administrator rights to create links. Native Windows Ctrl+C/junction/ACL, portable first launch, desktop rendering and authorised live acceptance remain unrun by this source task. A host blocked before the toolkit starts cannot produce diagnostic output: follow the security owner's approved allowlisting route.

## Fresh package gate

Test-Portable invokes the actual extracted bdit.cmd doctor JSON command before seeding evidence or launching WPF. It requires exit zero, clean standard error, the exact diagnostic kind/schema/version, Ready, every named mandatory check Required/Pass and every additional Required check Pass. The owned child drops an inherited BDIT_TOOLKIT_ROOT so it checks the extraction. Synthetic negative controls exercise the assertion separately; they never replace actual package output. The PowerShell 7 parser/assertion checks pass, including twelve refusal controls and two removed-guard failures. Actual Windows PowerShell 5.1 and extracted-package execution remain outstanding.

## Desktop Settings checks — PR #88

Expand Offline prerequisite checks in Settings and diagnostics, then choose Run offline checks. The local check uses the same engine as the doctor command. Cancel stops only this operation; closing waits for probe cleanup. Copy local result becomes available when a result completes. Required Unknown or failure prevents Ready. No tenant connection, host execution, installer or repair runs. Results remain separate from deployment evidence and publisher trust.
